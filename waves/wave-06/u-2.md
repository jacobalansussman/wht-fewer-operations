# u-2 (onerun): can every output be its neighbour plus or minus ONE run of inputs?

11 October 2026, about 01:40 to 02:20 EDT, 60-minute box. Private. One agent; nothing reviewed, nothing in Lean, nothing published.
Marks: [ran] = exact run of mine tonight (files in `u-2-onerun/`, whole numbers only; the searches are exhaustive unless I say
otherwise); [derived] = by hand tonight, checked by nobody but me; [read] = from tonight's reports; [guess].
Gate count everywhere: **(G)**, a gate is any a*u + b*v, scalings free. Count (O) is not used.

**No circuit below a known count, and no growth law below N log N. The result is a wall, with a proof: the "two running sums"
picture of subset sums cannot be linear, and for large N it is worse than the usual method.**

Words. N = 2^k points; an input or an output is a subset of {1..k}. *Subset sums*: y_S = sum of x_T over the T inside S.
*down(S)*: the set of inputs inside S (2^|S| of them). *Yates*: the usual method, (N/2) log2 N gates. *Picture*: the 0/1 table
"T inside S" with the outputs in one chosen order and the inputs in another. *Step*: two neighbouring outputs in the output
order (the last output's neighbour is "nothing", the zero row). *Difference of a step*: row S minus row S'; it is +1 on
down(S) minus down(S'), -1 on down(S') minus down(S), 0 elsewhere. *Run*: a maximal stretch of inputs, consecutive in the
input order, on which that difference is one non-zero value. *Corner*: a place where the difference changes value; the
two-chain program of q-cross costs N - 2 + corners gates, and corners >= runs. *One-run step*: a step whose difference is one
run. *Top of a step for an input T*: the one of the step's two outputs that contains T.

5. The reason, in one sentence: **runs that pass through one input are nested on each side of it, so the j-th longest of them

8. What the proof does not cover (section 4): output trees with very large hubs; signs or scalings on BOTH sides; letters

   dimensions. For the last one my method gives nothing at all; tried once (section 4): the regular tables triple per bit too.
9. Constants are poor: the bound is below N until k = 35. At sizes one can run it says nothing; it is a growth law only.

## 1. The yes-or-no question

Facts used [derived; the first three are the curator's, checked here on the 8-point solution].
- In the plain picture a one-run step joins two outputs with one inside the other, and its run is down(larger) minus
  down(smaller). So a path of one-run steps is a path through all subsets, neighbours always comparable, such that the N
  sets down(S_a) minus down(S_(a+1)) (and down(last)) are ALL consecutive in one order of the inputs. "Is there an order
  making a given family of sets consecutive" is the consecutive-ones problem; my test is an exact back-tracking placement
  (inputs with the same memberships are placed as one block; an input may be placed only if every set that is begun and not
  finished contains it).
- Signed version [derived]: if two neighbouring outputs carry different signs the difference is 2 at the empty input and 1
  elsewhere, never one run; so all output signs are equal. With input signs c, a step may also join two outputs that are NOT
  comparable, provided the symmetric difference of their down-sets is consecutive and c is constant on each of its two parts
  and opposite between them. I searched that too.

## 2. A reason one can state

**Three intervals.** Three intervals of a line that share a point: one of them lies inside the union of the other two.
Three intervals that meet pairwise share a point.

**Lemma A (two chains) [derived].** In a one-run picture (path or tree), fix an input T and look at the steps whose run
contains T. Their tops contain no three pairwise incomparable sets: the tops form at most two chains.
Proof: the runs are intervals through the point T; restricted to the inputs that contain T, the run of a step with top A is
exactly all inputs between T and A; if run 1 lies in the union of runs 2 and 3, the input A_1 lies in one of them, so A_1 is
inside A_2 or A_3.
Count for paths [derived]: every output that has a smaller neighbour is a top for some single element e; for each e the tops
form two chains among the sets containing e, at most 2k - 2 sets; at most half of the outputs have no smaller neighbour. So
N/2 <= k (2k - 2): **no one-run path for k >= 8** by counting alone. (The search says k >= 4.)

**The top and its co-atoms [derived]: no one-run tree for k >= 9.** Write C_x for the full set minus x.
(i) The edge from the full set to C_x has the run "all inputs containing x". Three such runs share the input {x,y,z} and each
owns a private input ({x}), so none is inside the union of the other two. So at most two C_x hang on the full set.
(ii) Every other C_x has an edge downwards, to some B_x strictly inside it or to nothing; its run D_x = down(C_x) minus
down(B_x) owns the private input C_x. So three such runs cannot share an input; so of any three, two are disjoint.
(iii) D_x and D_y are disjoint only if the input "full set minus x and y" is missing from one of them, which forces
B_x = C_x minus y or B_y = C_y minus x. Each x has one B_x, so there are at most m disjoint pairs among m such co-atoms.
(iv) By (ii) the pairs that meet form a graph without triangles on the m such co-atoms, so there are at most m^2/4 of them
(Mantel's theorem), and the disjoint pairs number at least m(m-1)/2 - m^2/4 = m(m-2)/4. With (iii): m(m-2)/4 <= m, so
m <= 6; and m >= k - 2 by (i). So k <= 8. (Plain version; fix ONE downward edge per co-atom in (ii) and (iii).)
For k = 5 to 8 the answer rests on the search at k = 5 and on:

**Monotone in k [derived].** Given a one-run tree at k + 1, keep only the outputs and inputs that contain the element k + 1
and delete that element from them. Runs stay runs in the induced order; an edge whose lower end lacked k + 1 becomes an edge to
"nothing" with run down(upper end); the tree with all other outputs merged into "nothing" is connected, so it contains a tree.
So a one-run tree at k + 1 gives one at k, and "no at 32 points" is "no from 32 points on".

## 3. The growth law: the nested-runs bound

Setting: any order of the inputs, any path through the outputs ending in "nothing", plain picture. For an input T let
c(T) = the number of steps whose difference is non-zero at T (the number of times "T inside S" changes along the path), and
S(T) = the total length of the runs through T (one run per such step). R = number of runs, V = total length of all runs.

**Step 1 (nested runs) [derived].** Sort the runs through T by how far they reach to the left of T. The part of the j-th run
to the left of T lies inside each of the first j runs. A run through T lies inside down(top of its step). Every output is the
top of at most two steps, so the first j runs have at least j/2 different tops, all containing a common set I; at most
2^(k - |I|) sets contain I, so 2^|I| <= 2N/j. Hence **the left part of the j-th run has at most 2N/j inputs**, the same on the
right, and S(T) <= 4N (1 + 1/2 + ... + 1/c(T)) <= 4N (1 + ln c(T)).

**Step 2 [derived].** R = sum over T of (sum over the runs through T of 1/length) >= sum over T of c(T)^2 / S(T)
(Cauchy-Schwarz for each T). With step 1: **R >= sum over T of c(T)^2 / (4N (1 + ln N)).**

**Step 3 (the path cannot keep c small) [derived].** For two different outputs S, S' with m = max(|S|, |S'|), the number of
inputs of size j inside exactly one of them is at least C(m-1, j-1). Summing along the path, the inputs of size j have total
count V_j >= (j/k) C(k,j) (2^(k-j) - 1/2); in particular V >= 3^k/2 - N/4 for EVERY path. Cauchy-Schwarz on each size:
sum of c(T)^2 >= sum over j of V_j^2 / C(k,j) >= 5^k / 100 (the sum of C(k,j) 4^(k-j) is 5^k, and j/k is about 1/5 where
it matters).

**Theorem [derived, unreviewed].** corners >= R >= (5/2)^k / (400 (1 + ln N)) for every pair of orders. Exponent
log2(5/2) = 1.32. With inputs negated: each run splits into its two sign classes and step 1 holds for each class; the bound
halves. For an output TREE in which every output has at most D neighbours: at least j/D different tops, bound times 2/D.

Checks [ran, `chain_check.py`, `chain_check.out`: every inequality of steps 1 to 3 separately, on q-cross's five best
pictures (4 to 64 points), on Gray and counting orders up to 128 points, and on 200 random pairs of orders per size up to 32
points and 30 per size at 64 and 128]: **all passed.** The largest S(T) / (4N (1 + ln c)) seen is 0.29, so the constant has
room. Measured on q-cross's best pictures:

## 4. What this closes, and the hatches

Closed, as far as a hand proof of one night goes: q-cross hybrid 1 and its section 4 ("no wall of the night covers this"),
WAVE6 brief 3 (this one), and the first target of briefs 1 and 2 (corners per point bounded): in two chains the subset-sum
picture needs at least about N^1.32 / log N corners. The route "transform = two two-chain subset sums" is not linear.
q-cross asked what nesting forbids where half-agreement forbade the transform's letters: **nesting forbids long runs through a
common input from many different outputs.**

Hatches, in the order I would try them:
1. **Running sums in two or more dimensions** (q-cross experiment 8, the "spreadsheet trick"). Put the inputs in a table,
   keep the table of running totals (2N gates), a step is then a few boxes. Boxes through one cell are NOT nested: a wide flat
   box and a tall thin one overlap in a small box, and a staircase of j boxes covers an area that step 1 cannot bound. My
   bound degrades to V / (N log N), which is below N. [derived] The weaker condition that survives for boxes in d dimensions:
   of any 2d + 1 boxes through a cell, one contains the intersection of the others, so the tops through T cannot contain
   2d + 1 sets each missing a private element of a common (2d+1)-set; a counting bound of the Sauer-Shelah kind then gives
   at most about k^(2d) tops per input for ONE box per step, so one box per step still dies for fixed d [derived, rough], but
   "a few boxes per step" is open.
   Pushed once [ran, `mst2d.py` on the Linux machine, whole numbers, `t2d_*.out`; the tool reproduces the one-chain numbers
   41 and 31 at 16 points when the table has one row]: cost of a step = non-zeros of the mixed second difference in the table,

   10, 27, 68, 180, 496, 1407 for tables 2x4, 4x4, 4x8, 8x8, 8x16, 16x16 (2x8: 24). Per point 1.25, 1.7, 2.1, 2.8, 3.9, 5.5:

   So the regular two-dimensional tables are no better than one chain (one chain, best found: 10, 27, 70 at 8, 16, 32
   points). What stays open is an irregular table, for which I have neither a bound nor a good search.
2. **Trees with huge hubs.** Step 1 needs "an output is the top of few steps". Stars are covered (every output hung on

3. **Signs or scalings on both sides.** A step between outputs with different scalings has support down(S) union down(S'),

## 5. Mutations ("yes, and")

- The failure of "one run" is made of nested intervals. First way round: more than one order (q chains of running sums, a run
  may be consecutive in any of them): Lemma A gives 2q chains of tops, the count needs q of order N / k^2: worse, dropped.
- Second way round: outputs on a tree: gains one size (16 points), dies at 32 on six outputs.
- Third: negate inputs: gains nothing at 16 and 32 points.
- Fourth: two-dimensional tables: the nesting disappears (hatch 1). Tried once: the regular tables triple per bit like the
  chain; only the 2x4 table reaches weight N.
- A better search for whoever continues brief 1: for a fixed input order the best output TREE is a minimum spanning tree,
  exact and fast, so only the input order need be searched (`mst.py`); W <= corners always.

## 6. Criticism, last

- The theorem is a hand proof of one hour. Its three steps were each checked numerically on real and random pictures, which
  tests the inequalities, not the logic of the asymptotic sum; the last line (5^k / 100) is a crude estimate of an exact sum
  that the table evaluates directly. A second reader should check step 1 first: "at least j/2 different tops, all above I".
- It is a bound in a MODEL (two chains, plain or inputs negated). It is not a lower bound for subset sums with subtraction.
- It is far from sizes one can run: below N until k = 35. Nothing here says the 16- to 128-point searches of brief 1 cannot find
  small counts; it says they cannot continue.
- The two exhaustive "no" rest on my own consecutive-ones test, written twice (C and Python) by the same author; the node
  counts agree exactly, which checks the code against itself and not against a published PQ-tree implementation.
- "No one-run tree for k >= 5" uses the monotonicity argument, three lines by hand. The by-hand proof for k >= 9 is
  independent of the search.
- I did not extract the forbidden configuration at 32 points by hand; I only know it lives on the full set and its five
  co-atoms and is not one of the three-set conditions.
- The signed search assumes my derivation that all output signs must be equal in a one-run picture.
- I did not search the literature (range sums, dominance sums in the group model); a bound of this kind may be known.
