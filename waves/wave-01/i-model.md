## 0. The model in one paragraph

Files: `R/OAI/Computability/FourierTransform/RAM.lean`, `Goal.lean`, `R/OAI/Computability/FourierCircuit/Core.lean`.

The machine has two number systems that never meet. [read]

- **Integers** (`Ty.w`, natural numbers): add, truncated subtract, multiply, divide, remainder, compare (`NOp`, RAM.lean:153), test for zero (`ifz`, :206), index arrays, write at computed addresses (`sow`). Every integer produced is recorded (`Bill.word`, :135) and must stay below `(n+2)^cBound` (Goal.lean:51, :57). Small and clever.
- **Complex numbers** (`Ty.c`), exact, any size, one unit per operation: add, subtract, multiply by a *scalar* (`scale : p sc (c t) → c t`), invert a scalar (`inv : sc → sc`). No comparison, no rounding, no remainder, no product of two data values in the transform (`cross` needs `allow = true`; the goal uses `Prog false`, Goal.lean:48). Big and dumb.
- No atom has a complex input and an integer output. No atom turns data (painted `left`) into a scalar. The header says it in words: "Scalar and data field registers are separated. Tests and loop/request sizes are on nonnegative integer registers." (RAM.lean:27)

**Consequence [derived].** For each length n the run is a fixed list of additions and scalings of the data: control flow cannot depend on the data, and every data operation is linear. So work ≥ size of a linear circuit for the transform over the field generated by the supplied root. No power of the integer side (tables, branching, indirect addressing, division) can lower the count of data operations; those powers only pay for bookkeeping. Linear size in this model is exactly: a linear-size linear circuit with arbitrary exact coefficients, whose wiring a word machine can write down in O(n).

**The sentences that kill Kronecker packing.** (1) `∀ x : Vec n` with `Vec n = Fin n → ℂ` (Goal.lean:14, :55): inputs are arbitrary complex numbers, and a linear map from n numbers to one number forgets n − 1 of them. (2) No atom from `c` to `w`: nothing can take a remainder or integer part of a complex number. (3) `result.peak ≤ cap`: integers stay at O(log n) bits. Branching on data and data-indexed tables die on (2) alone.

## 2. Ideas

### Idea 1. The outrageous program, written in the variant that allows it
Variant: data are integers of bounded size; integers are unbounded; multiply and remainder cost 1.
Program [ran, exact, lengths 4, 16, 64]: choose N primes p_w, one per output; let r_i be the integer that is ≡ −1 modulo the primes whose index has bit i set and ≡ +1 modulo the others; R_y = product of r_i over the set bits of y (N multiplications, no data). Then F = Σ x_y·R_y (N multiplications, N additions) and output_w = F mod p_w (N remainders). **3N data operations, any length.** The same works for any matrix with small integer entries; the multiplicative structure of this one makes the preparation O(N) too.
Second program [ran, exact, lengths 16, 256, 1024]: the whole array in one integer, fixed-width fields; each butterfly layer is 16 whole-integer operations (and, shift, add, subtract, xor). **16·log₂N operations for the transform itself**: 160 at length 1024.
What it taught: the packing needs one number that is both big (holds everything) and clever (can be taken apart). OpenAI's model splits those two properties between its two number systems. Mutation: idea 2 keeps both on the integer side.

### Idea 2. A linear exact transform inside OpenAI's own machine, for data in a fixed finite ring
Put the data on the *integer* side (arrays of `w`): entries modulo a fixed 2^b or a fixed odd prime p. A word holds c·log n bits for any constant c, so one word holds L = Θ(log n / log p) entries. Layers that pair entries in different words: field-wise add and subtract on whole words, O(1) per word (the 16-operation kernel of idea 1 is exactly this). Layers inside a word: one lookup in a table of size n^ε, built once. Cost: (N/L)·log N = O(N·log p) word operations [derived]. **Linear, exact, in the RAM as written, for a transform over a fixed finite field.**
Limits [derived]: with word-sized entries (p about n^c, or exact integer outputs, which need log N extra bits) the gain is a factor 2 at most; several small primes and the Chinese remainder theorem give N·(b + log N) again.
This is the variant closest to real machines: it is bit-slicing, what fast code for Boolean functions does.

### Idea 3. Spend the unused power: ill-conditioning
[derived] Morgenstern's bound is log of the determinant. For the *unitary* transform the determinant is 1 and the bound is zero; the n log n comes only from scaling n outputs by √n with bounded coefficients. In OpenAI's model that scaling costs n. So the bounded-coefficient theorem says nothing about any program here, and the published constructions, with entries of size at most 1, use the "any size" power only for the last rescaling.
[guess, from memory of Ailon's papers 2013 to 2019, not re-read] the lower bounds that do survive for the unitary transform are for well-conditioned programs: n log n for 2×2 unitary gates, and a speed-up forces intermediate states with large condition number. Read backwards: **a linear program must be violently ill-conditioned; exactness without stability is precisely the licence for that, and nobody is using it.**
Construction to start: allow shears [[1,B],[0,1]] with B a free huge parameter in the tiny game; search for identities that hold for every B (or as B → ∞ with error a polynomial of fixed degree in 1/B, then cancel the error with a fixed number of values of B, as in the border-rank trick for matrix multiplication). First measurement: the condition number of the intermediate states of the published unit, per level.

### Idea 4. The transform as a short sum of cheap tensor products
A tensor product of 2×2 factors, each singular or monomial (diagonal or anti-diagonal), costs at most about 3N: fold on the singular columns, scale, fan out [derived]. Write the transform as a sum of q such products.
[ran] N = 8: with K the matrix (−i)^(Hamming distance), which is the transform between two free diagonals, **K = 2·I + 2i·(antipode) − ((1+i)/2)·(all ones) − ((1−i)/2)·(parity ⊗ parity)**: two monomial terms and two rank-one terms, no recursion. It is the cubic through the four cheap points t = 0, ∞, 1, −1 of the family t^(distance).
[ran] With letters Z, X, Z+iX, Z−iX (two monomial, two singular; the transform's factor is Z+X): fewest products is 3 for two columns (16 solutions, e.g. (Z+iX)⊗(Z−iX) + (1+i)·Z⊗X + (1−i)·X⊗Z, checked by hand too) and 4 for three columns (16 solutions, some not symmetric: ZZX, XXZ, PPM, MMP).
[derived] Lower bounds: any alphabet not containing the factor itself needs q(k) ≥ k + 1 (contract one position with a functional that kills one term). A finite alphabet of L letters on one line needs q(k) ≥ (L/(L−1))·q(k−1): exponential, so 4 columns already need 6.
What it taught: k + 1 terms is the floor, reached at 1, 2, 3 columns; a finite cheap alphabet explodes; and (k+1)·3N is above the textbook's kN unless terms share work. The rank-one + monomial version is killed beyond N = 8 by the classical rigidity bound (rank × sparsity ≥ N/4). Mutation: idea 5, bigger letters.

### Idea 5. Half-rank letters, the Grover form, and "the transform is a transpose in disguise"
[derived] A tensor product of f factors of size d, each of rank at most d/2, costs a geometric series: the array halves after each factor, so the total is O(N) whatever the factors are. And the transform's factor sits on a line with such letters: H_d = √d·I + (rank d/2).
[ran] A better form exists. H_4 equals 2I − J (J = all ones) after signed permutations of rows and columns: it is the Grover diffusion step on 4 points. For G = (2I − J)^⊗f the rank of G − √N·I is 1, 6, 28, 120 at N = 4, 16, 64, 256, that is **C(√N, 2)**, against N/2 = 2, 8, 32 for the usual form. [derived] No monomially equivalent form does better: the trace of a flat unitary is at most √N.
Pretty consequence [derived]: G/√N has +1 on a space of dimension C(√N+1, 2) and −1 on C(√N, 2): the spectrum of the *transpose* map on √N × √N matrices, split into symmetric and antisymmetric. The transpose is a free relabelling. So H = Q·(transpose)·Q⁻¹ for every Q carrying symmetric matrices to the +1 space and antisymmetric to the −1 space, and that family of Q has about N²/2 free parameters. The textbook Q is a tensor power. **Find a Q that is not.**
Also [derived]: G is a product of f commuting reflections, one per base-4 digit, each "subtract twice the digit average". If the averages were nested (a chain, as in a wavelet transform) the product would cost O(N) by a geometric series; here they form a Boolean lattice and cost N per digit. Linear size = replacing the lattice by a chain.
In OpenAI's count (scale charged) the unitary 4-point step is 3 adds, 1 scale, 4 subtracts = 8, the textbook rate. In the usual count (a gate is any two-term combination) it is **7, not 8** [derived count: 3 gates for the sum s, then 2x − s four times; the equivalence itself is ran].

### Idea 6. Pointer trees: relabelling at geometric cost, zeros for free
[read + derived] Store the array as a tree of arrays of arrays, one level per digit column. A relabelling of column j by a function of columns 1..j (the column-mixing step of the floor note's hatch (b)) permutes pointers at depth j: d^j units, not n. Summed over all columns that is a geometric series, O(n) for all of them together, where a flat array pays n each. Scaling entries still costs n; only the address half of a monomial step becomes free.
Second half: a fresh row of an array of arrays is the empty array and reads as zero. So zero scratch arrays cost one pointer each, and an integer tag beside each pointer lets `ifz` skip a whole child call on a known zero array. OpenAI's single-array call "zero-fills W* − 1 arrays" [read, reader report]; in the RAM as written those can be virtual.
What it does not do [derived]: lower the linear-circuit count. It removes address costs, which is what hatch (b) and "blocks run only on known zeros" were charged for.

### Idea 7. A model in which the transform is free, and the search for a one-sided way in
[ran, exact] In the Bell basis of two columns, H⊗H is a signed permutation: Φ+ → Φ+, Φ− → Ψ+, Ψ+ → Φ−, Ψ− → −Ψ−. [derived] In general, in the basis "characters on the cosets of a self-dual code", the whole transform is a signed permutation. [ran] For cyclic length m² the Zak transform Z (a length-m transform on each of m residue classes, m² non-zero entries per m rows) does the same: Z·F·Z⁻¹ has one non-zero entry per row and per column at m = 2, 3, 4, 5, 6, each at three primes (a zero modulo one prime could be false; three independent primes up to 10⁹ agree). Reaching that basis costs half the columns, coming back the other half: 2·(k/2) = k, the textbook again, by a different recursion, t(n) = 2·t(√n) + 1.
The idea: fan-out is free, so the representation need not be a basis. Look for an overcomplete set of O(N) atoms, closed under the transform up to phases, with a cheap analysis map A and a cheap synthesis map S, S·A = I; then transform = S·(monomial)·A. A one-sided version, t(n) = t(√n) + O(1), would be n log log n.
Clue [derived]: H = 2R − J, where R is the 0/1 matrix "w·y is even", the point-hyperplane incidence matrix. The transform is a Radon transform plus a rank-one term; the atoms are indicators of hyperplanes and their intersections.

### Idea 8. Which variants are linear, and how real are they

| Variant | Transform cost | Closer to real machines than OpenAI's? |
|---|---|---|
| Unbounded integers, remainder at unit cost, integer data | 3N [ran]; 16·log₂N after packing [ran] | No: one operation hides N·log N bit operations |
| Data in a fixed finite ring, words of log n bits | O(N) [derived] | Yes: bit-slicing |
| Fixed relative precision, random rounding, words of log n bits | O(N·(log(1/ε) + log log N)) [guess: errors add as a random walk over log N layers, so ½·log log N guard bits] | Yes for small ε; overflow needs care |
| Gate = any two-term combination, scale free | 7/8 of the textbook at the first step [derived count on a ran identity] | same model, different constant |
| Cost = number of non-monomial steps | k (the tiny game) | No |
| Data comparisons or products allowed | no gain [guess: a branch taken on an open set computes the linear map there; degree-1 parts of a nonlinear circuit cost a constant factor] | |

Reading: on real machines a transform is a bit-level object, and a log factor is recoverable by packing whenever precision is below the word size. OpenAI's model asks the opposite question (infinite precision at unit cost), and there only the scalar side can be exploited.

### Idea 9. The transform as line sums of a finite plane: a target of n log log n
Found last, by following idea 7's clue. Take N = q², q = 2^m, and view the addresses as the plane over the field with q elements. Its q + 1 directions cut the non-zero frequencies into q + 1 classes of q − 1 (a *spread*). The slice theorem: the transform restricted to one class is the length-q transform of the q sums of the data over the parallel lines of the matching direction.
[ran, exact] Lengths 4, 16, 64, 256 (`play4.py`): fold onto the q lines of each direction, run q + 1 transforms of length q, read off all N outputs; equal to the textbook transform every time. The N + q sums are exactly the lines of the plane (6, 20, 72, 272 of them).
[derived] Write Rad(q) for the cost of all N + q line sums and T for the transform. Then T(N) ≤ Rad(√N) + (√N + 1)·T(√N), and in the other direction Rad(√N) ≤ T(N) + (√N + 1)·T(√N) + O(N). So:
- **all line sums of the plane in O(N) operations would give the transform in O(N log log N)**, since the cost per entry then obeys t(N) = t(√N) + O(1);
- a linear transform would give linear line sums; the two problems are tied.
The object is concrete: N + √N sums of √N points each, any two sharing at most one point. Without subtraction it costs N^1.5 and that is provably best possible for sums alone [guess: the classical bound for matrices with no 2×2 block of ones, from memory]; with subtraction the only known way is through the transform itself, about 1.5·N·log₂N. Naive counts met: 6, 60, 504, 4080 additions at N = 4, 16, 64, 256, against the textbook transform's 8, 64, 384, 2048; the naive fold already loses at N = 64.
Why it is not the textbook in disguise: one level uses *only* folds (fan-out and fold, the floor note's hatch (c)) along directions that are column-mixing relabellings (multiplication by a field element, hatch (b)), and the pair-diagonal potential is moved by every one of them. The whole question is whether √N + 1 folds can share work through cancellation.
Start: the 20 line sums of the 16-point plane. Naive 60 operations. Search for 59 or fewer with subtraction allowed.
