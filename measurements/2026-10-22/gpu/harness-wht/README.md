# gpu/harness-wht: the circuits on an NVIDIA GPU

`run.sh` times three things on one GPU (22 October 2026: an NVIDIA RTX PRO 6000 Blackwell Server Edition, compute
capability 12.0, driver 580.82.07, CUDA 13.0, PyTorch 2.11):

- **A. Row kernels** (`wht_cuda.cu`): one thread block transforms one row of 256 to 4,096 points held in shared
  memory; each thread runs an 8- or 16-point step in registers, the textbook or a circuit (19, 22, 52 or 56
  operations, `kernels_cuda.h`, generated by `gen_cuda.py` from `circuits/`). Also the register stage alone.
- **B. Dao's kernel** (`bench_dao.py`): Dao-AILab's fast-hadamard-transform, fetched at commit `e7706faf`, built
  twice, once as published and once with its per-thread 8- and 16-point stage replaced by the 19- and 52-operation
  circuits (`patch_dao.py`). HadaCore (tensor cores), from pytorch-labs/applied-ai, is timed beside it where it
  builds; the script fetches that repository's latest commit, which on 22 October was `2391954b`.
- **C. FFT libraries** (cuFFT and VkFFT): this part failed in both launches and gave no results.

Every program checks its output before it is timed (`wht_cuda_check.txt`, the CHECK lines of `bench_dao.txt`), and
a deliberately broken copy must fail. Results: [../../README.md](../../README.md), section "GPU".

## Run it again

On a machine with an NVIDIA GPU, CUDA 13 (`nvcc`), PyTorch with CUDA, git and about 12 GB of memory, idle:

    bash run.sh

About 25 to 50 minutes, most of it building Dao's kernel twice and VkFFT. `SKIP_DAO=1` and `SKIP_VKFFT=1` skip parts
B and C. Off Colab, give the two working folders, since the defaults are under `/content`, Colab's working folder:
`K0SRC=$HOME/k0src KBUILD=$HOME/k0build bash run.sh`.

The script fetches HadaCore's newest commit, and only when the folder `$K0SRC/applied-ai` is missing. To time the
code of 22 October instead, put that commit there first:
`git clone -q https://github.com/pytorch-labs/applied-ai.git $K0SRC/applied-ai && git -C $K0SRC/applied-ai checkout -q 2391954b19988bd76cf3c2ea84c1ce74b68d568b`
(with `K0SRC` set, as above, or `/content/k0src` in its place).

## Check the CUDA code without a GPU

`wht_cuda_cpucheck.cpp` compiles the device code of `wht_cuda.cu` as plain C++ and runs every stage on the CPU:

    clang++ -std=c++17 -O1 wht_cuda_cpucheck.cpp -o cpucheck && ./cpucheck

On an Apple M4, macOS, Apple clang 21.0.0, 22 October 2026, it printed 12 PASS lines (sizes 256, 512 and 4,096;
textbook and circuits), the broken copy CAUGHT, and `ALL PASS`.

## Failures, kept

The first launch failed to build: CUDA 13 removed a field (`cudaDeviceProp.clockRate`) that `wht_cuda.cu` read, and
PyTorch's build needed a folder that did not exist yet. Its log is in `../runs/rtx6000-wht-failed-build/`; the
fixes are in `before-cuda13-fix.diff` and `before-mkdir-fix.diff`. The VkFFT part (C) failed in both launches, on
another CUDA 13 change, and was not fixed.
